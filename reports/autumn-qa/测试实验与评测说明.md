## 新增 63 个 pytest 接口用例

新用例位于 `tests/pytest_api/test_contracts.py`，使用参数化表达接口与输入的组合；fixture 为每个用例创建独立 SQLite 数据库和应用实例，结束后释放连接。模型客户端固定为 Stub，RedisRuntime 使用本机内存实现。HTTPX 驱动的 FastAPI TestClient 直接调用 ASGI 应用，不需要启动公网服务。

| 用例组 | 数量 | 验证内容 |
| --- | ---: | --- |
| text 字段边界 | 24 | 3 个接口 × 缺失、null、空串、空白、整数、布尔、数组、对象 8 种输入；应返回 400，世界和对话不发生变化 |
| JSON 解析与对象类型 | 15 | 3 个接口 × 截断 JSON、非法 UTF-8、JSON 数组、null、字符串；应返回 400 |
| CSRF | 9 | 3 个接口 × 缺失、格式错误、其他令牌；应返回 403，世界状态不变 |
| 正常回合 | 2 | 中英文 locale 下移动到码头，响应中的回合和状态哈希应与后续读取一致 |
| 非法业务动作 | 3 | 不可达移动、远处取物、缺少物品时使用；请求返回 200，但业务事件明确失败且状态不变 |
| 流式完成 | 1 | SSE 仅有一个 done，且无 error，完成后的状态确实可读取 |
| 同步超时 | 1 | 先执行内存动作再注入 TimeoutError；返回 502，状态恢复，下一次有效请求仍可成功 |
| 流式超时 | 1 | 生成过程发生异常；只报告 error，不发送 done，不保存半完成状态 |
| 写入版本冲突 | 1 | 注入 RuntimeConflict；返回 409，重新读取仍为已持久化状态 |
| 重复审批 | 1 | 同一任务第二次审批被拒绝，动作仅执行一次 |
| 跨用户存档 | 1 | 另一用户不能列出或加载原用户存档，自己的世界不变 |
| 限流边界 | 1 | 配额为 2 时前两次通过，第三次 429 且带 Retry-After；另一会话不受影响 |
| 游客权限 | 3 | 游客不能访问管理员/账号调查列表，但可以读取自己的设备会话 |

这里的超时是测试主动注入的故障，目的是验证异常响应与状态恢复，不是测量真实供应商网络延迟。

## 实际发现并修复的问题

28 个失败用例对应 3 类缺陷，并非 28 个独立缺陷。

| 问题 | 修复前表现 | 修复 |
| --- | --- | --- |
| 非法 JSON 或非对象请求体未校验 | JSON 解析失败，或数组/null 没有 get 方法，导致 500；15 个用例复现 | 在 3 个文本接口入口统一解析 JSON，要求对象请求体，错误返回 400 |
| 非字符串 text 字段处理不一致 | 回合接口对整数/布尔等调用 strip 导致 500；聊天接口将非文本强转字符串并接受；12 个用例复现 | 明确要求非空字符串，在进入可变世界事务前拒绝非法输入 |
| 同步回合未处理管线超时 | 注入 TimeoutError 后返回 500，调用方无法识别超时；1 个用例复现 | 返回带 model_timeout 错误码的 502，并利用现有事务异常路径丢弃未提交缓存 |

修复范围是 `/api/turn`、`/api/turn/stream`、`/api/agents/chat` 的文本输入，以及同步回合的管线 TimeoutError。其他请求体接口和供应商所有异常类型没有在本轮全面审计。

## 本次离线评测怎么做

### 世界事实与长程状态

`everstory/eval/episodes.py` 定义固定动作序列及已知答案。三个短场景分别检查钥匙/打火石/锁状态、油壶归属、灯塔点亮等问题。EverStory 共答对 6/6 个事实问题；60 回合巡游在第 20、40、60 回合分别查询 3 个保持不变的事实，每个检查点均为 3/3。

事实召回率 = 答案命中数 / 事实问题总数。当前答案命中使用不区分大小写的子串匹配。

EverStory 的这一指标直接读取规则引擎状态，因此高分验证的是结构化状态路径。Stub 模式下 pure-llm 和 summary-memory 返回占位输出，两者的 0 分不能用于证明 EverStory 比真实模型更强。真实模型的记忆衰减或叙事矛盾率需要另行调用模型验证。

### Agent 完整案件

`everstory/eval/team.py` 每次从全新灯塔案开始，按预先定义的调查路线执行移动、访谈、证据检验、分析复核和最终指控；额外构造过期任务和未经审批讨论场景。每次指标如下：

| 指标 | 定义 | 本次每次结果 |
| --- | --- | --- |
| 行动提案准确率 | 动作类型及目标参数完全符合预期的提案 / 8 个计分提案 | 8/8 |
| 审批动作成功率 | 规则引擎返回成功的计分审批动作 / 8 个计分动作 | 8/8 |
| 未经授权状态修改 | 发出讨论/提案前后，状态哈希或回合发生变化的次数 | 0 |
| 过期任务拒绝 | 提案后独立移动，再审批旧任务；要求拒绝且状态不变 | 通过 |
| 证据关联率 | 能关联已完成任务、有细节、确认回合合法的证据 / 9 条证据 | 9/9 |
| 完整案件完成 | 最终规则引擎 case_solved 标志是否成立 | 是 |
| 调查记忆恢复 | 序列化再恢复后，消息、任务、证据数量是否一致 | 31 条消息、10 个任务、9 条证据均一致 |

三个重复运行均通过。审批成功率的分母只包含 8 个计分动作，不包含所有辅助移动或复核步骤。记忆恢复指标目前检查数量，证据关联检查结构和时间合法性，均不等于逐字段等价或完整语义正确性。

## 历史真实模型的 98.8% 怎么算

仓库原始报告生成于 2026 年 8 月 27 日。本次仅重新计算保存的输出，没有重新请求模型。

- 8 类角色各定义 3 个固定案例，共 24 个不同案例。
- 每个角色有若干候选模型，共 23 个“角色 × 模型”组合，所以产生 69 个角色案例结果。
- 每个案例的加权分数 = JSON 格式 15% + 任务正确性 55% + 事实落地 20% + 语言一致性 10%。
- JSON 无法解析时该案例为 0 分；任务分检查预声明的字段、目标和等价枚举。
- 事实落地分 =（要求的事实 ID 命中比例 + 未出现禁止内容的得分）/ 2；这是一种规则近似，不是完整语义蕴含判断。
- 语言检查主要使用中英文字符规则；单案例达到 0.8 视为通过。
- 先对每个组合的 3 个案例取平均，再选择每个角色的最佳模型，对 8 个推荐角色的平均分再取平均，得到 0.9875，即 98.75%，显示为 98.8%。最低推荐角色分为 93.33%。
- 另有 6 条跨角色信息交换链，检查确认事实传递、来源保留、污染信息拒绝和过期事实处理；以及 3 次完整案件。
- 原报告汇总记录为 123 次调用、118,513 Tokens；本次 69 个角色案例的复算与原分数全部一致，失败记录也保留。

最佳路由是在同一批固定案例上选择并评分的，目前没有独立留出测试集。因此 98.8% 不能表述为普遍准确率、产品整体正确率或多智能体优于单智能体的证据。下一步若运行真实模型实验，应先冻结评分规则，再使用新的案件和独立用例，重复采样并报告失败率及分数分布。

## 如何复现与查看证据

在 PowerShell 中运行：

```powershell
cd EverStory
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[web,production,test]"
.\.venv\Scripts\python.exe -m scripts.run_autumn_qa
```

脚本先运行全量 pytest 并生成覆盖率，再运行离线短场景、60 回合评测、三次完整案件和历史输出复算。若已运行测试且只想重新生成评测数据，可加 `--skip-tests`。仓库保存结果摘要及离线评测数据；原始 XML、日志、环境快照和逐行覆盖率报告由脚本在本地生成，CI 的 XML 报告通过 Actions 产物下载。

- `experiment-summary.json`：环境、提交、测试计数、覆盖率和历史审计摘要。
- `environment-freeze.txt`：本次 Python 包版本快照。
- `final-tests.xml`、`final-tests.log`：JUnit 结果和原始测试输出。
- `coverage/index.html`：可浏览的逐行覆盖率报告。
- `offline-evaluation.json`、`offline-evaluation.md`：本次离线评测原始数据及表格。
- `historical-score-audit.json`、`historical-rescored.md`：历史输出复算结果。

本轮实测环境为 Windows、Python 3.12。CI 配置已接入 pytest、JUnit 和覆盖率产物上传；本地实验记录不代表 Python 3.11 或 Linux 的新增流程已通过，线上结果以 GitHub 检查为准。当前依赖组合有一条 Starlette 对 HTTPX 测试适配的弃用提示，不影响本轮用例通过，后续升级应关注兼容性。
