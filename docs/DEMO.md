# EverStory — 90 秒面试演示脚本

启动：`docker compose up --build`，打开 <http://127.0.0.1:8123/>。为保证面试
稳定，在模型控制台选择 Offline Stub；完整多模型指标已经保存在
`reports/agent-routing-evaluation-zh.md`。

## 0–15 秒：一句话架构

> “这是一个状态一致的多智能体破案游戏。核心原则是 LLM 提案、状态机裁决：模型
> 负责理解和叙述，但地点、物品、证据与结局永远由确定性世界状态管理。”

指出开场位置是“风暴海岸”，玩家身份是刚被冲上岛的首席调查员，而不是莫名其妙
出生在守塔人木屋。

## 15–45 秒：证明模型不能越权

点击路线进入“守塔人小屋”，在主聊天输入：

```text
examine the annotated tide chart
```

> “这是关键证据，主聊天会明确拒绝并引导进入联合调查室。不是靠 Prompt 口头约束，
> 而是回合管道的权限边界；世界回合和证据状态都不会变化。”

按 `G` 打开联合调查室，输入：

```text
@field examine the annotated tide chart
```

批准任务并切换案件板：

> “现场调查员只能提出结构化任务。玩家批准后，引擎重新验证人物、物品、地点和任务
> 是否过期，再把带来源智能体、任务 ID、地点和确认回合的记录写进证据板。”

## 45–70 秒：展示真正的多智能体价值

在群聊发送一条假设，例如：

```text
The storm alone proves the failure was accidental.
```

> “分析员先形成待验证假设，质疑者会引用上一位成员并要求可证伪证据。只有三份证词、
> 三条物理/时间线证据和分析员复核全部完成，案件主管才能正式指控。”

指出案件板顶部的 `证据链 n/7`，以及每个成员独立的头像、名称和模型路由。

## 70–90 秒：量化与工程完整度

打开 `/settings` 的 Diagnostics：

> “每个角色可以共享或独立配置 OpenAI-compatible API。真实方舟评测覆盖 23 个
> 角色—模型组合、6 条信息交换链和 3 个完整案件；推荐路由平均 98.8%，信息传递、
> 证据落地和破案均为 100%。项目还有 133 项离线测试、Python 3.11/3.12 CI、Docker、
> 双语 UI 和完整存档。”

## 高频追问

**为什么不直接让一个模型记住全部状态？**

长上下文和摘要都可能漏掉事实。EverStory 每回合从结构化状态重新渲染上下文，拒绝
原因和结果来自规则引擎，因此模型无法用自然语言“争辩”出一个不存在的状态。

**这算真正的多智能体吗？**

它是有独立身份、职责、路由、互相引用和协议边界的多智能体协作系统。价值不在角色
数量，而在分工产生的可测流程：现场取证、分析复核、反方质疑、主管结案。

**玩家是否多余？**

玩家是首席调查员，负责提出方向、批准成本和承担最终判断。移除玩家会变成自动跑完
的演示；保留玩家后，智能体提供信息增益而不替玩家做决定。

**生产化还缺什么？**

当前是完整的本地作品集版本。上线多人服务还需 Postgres/Redis、认证、限流、密钥
管理和多实例会话协调；这些边界在 Roadmap 中明确记录。
