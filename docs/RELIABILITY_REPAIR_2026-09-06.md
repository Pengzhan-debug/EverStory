## 部署注意事项

1. 先备份数据库并在 staging 环境验收。新版本需要执行 `python -m alembic upgrade head`，新增 `player_sessions.runtime_revision`。
2. 已有 `scripts/render-start.sh` 会在启动前迁移；自行运行 Uvicorn 时也必须先迁移。不要仅靠 `create_all` 升级既有表。
3. **不要让旧版本与新版本同时写同一存档。** 旧 worker 不执行 revision 校验；首次升级应安排停止旧 worker 的短维护窗口，随后统一启动新版本。
4. 公网部署保持 `LLM_ALLOW_PRIVATE_ENDPOINTS=false`。只有可信本地开发环境才可开启；它不是玩家控制台选项。
5. 固定 IP 的 HTTPS 传输禁用了环境代理。依赖代理的网络需要单独设计可信出口；不要为了连通性在公网关闭地址限制。
6. 多 worker 部署需真实 Redis，建议同时启用基础设施严格模式。没有 Redis 的内存协调仅支持单进程；数据库 CAS 能拒绝冲突，但不能消除重复模型请求费用。
7. 推送后检查新增 infrastructure CI，再验证 `/api/health`、双设备继续同一案件、存档/读档、后台重启恢复和一条受预算限制的真实 API 请求。
8. 此次迁移不删除旧数据。若回滚代码，先停新 worker；通常保留新增列即可，不必删除数据库或存档。
